build: local release build script that injects the OAuth client id at compile time

Upstream already has the mechanism: EnvironmentInteropGenerator reads the
environment at compile time and, when PCL_WRITE_SECRET is set, bakes every PCL_*
variable into SecretDictionary (minus the prefix). Secrets.MSOAuthClientId then
reads MS_CLIENT_ID from it. So no code change is needed and nothing has to be
committed - the id only ever lives in the environment or a gitignored file.

The catch is that the compiler and MSBuild servers are long-lived and cache the
environment, so exporting the variable and building silently produces a binary
without the id. Verified: with the servers running the id is absent from
PCL.Core.dll; after 'dotnet build-server shutdown' it is present.

tools/build-release.ps1 wraps all of this: it reads the id from PCL_MS_CLIENT_ID
or .secrets/ms_client_id.txt, shuts the build servers down, publishes for the
requested targets, writes run.sh for the Linux output, and then re-reads the built
PCL.Core.dll to confirm the id really is embedded.

.gitignore now ignores .secrets/, *.local.props and Directory.Build.local.props.

README documents both the Debug (env var) and Release (compile-time) paths.

Note for Windows 5.1: the script is saved as UTF-8 with BOM, without which the
older shell parses the Chinese strings as GBK and fails to load the file.
